# Garment disruptor rule analysis

[![Analysis DOI](https://zenodo.org/badge/DOI/10.5281/zenodo.20037099.svg)](https://doi.org/10.5281/zenodo.20037099)
[![Dataset DOI](https://zenodo.org/badge/DOI/10.5281/zenodo.20006389.svg)](https://doi.org/10.5281/zenodo.20006389)

This repository contains the Python workflow and derived audit tables for the disruptor-rule analysis reported in the manuscript:

> **Embedded garment features limit textile sorting and fibre-to-fibre recycling in fast fashion**

The workflow applies rule-based disruptor indicators to a component-normalized garment-variant dataset and produces row-level flags, summary statistics, match evidence, diagnostic rankings, category diagnostics, regex inventories, and hardware material-disclosure summaries. The repository is intended to make the manuscript results reproducible, auditable, and reusable.

## Input dataset

This workflow uses the component-normalized garment-variant dataset developed in the companion dataset repository:

- Dataset repository: https://github.com/kai-li-1994/garment-variant-dataset
- Archived dataset release: https://doi.org/10.5281/zenodo.20006389

The rule-evaluation script expects the following input file in the working directory:

```text
6_JSONL_component_normalized.jsonl
```

This file is not duplicated in this analysis repository because it belongs to the companion dataset-construction release. To rerun the analysis, download or copy `6_JSONL_component_normalized.jsonl` from the companion dataset release into the same directory from which you run `scripts/01_evaluate_disruptor_rules.py`, or update the `input_file` path inside the script.

## Scripts

| File | Purpose |
|---|---|
| `scripts/01_evaluate_disruptor_rules.py` | Applies the disruptor-rule framework to `6_JSONL_component_normalized.jsonl`. It generates row-level rule flags, rule summaries, aggregate summaries, match-evidence records, trigger diagnostics, category diagnostics, regex inventory, hardware material-disclosure diagnostics, and a readable text summary. |
| `scripts/02_generate_figures.py` | Reads the output tables generated by `01_evaluate_disruptor_rules.py` and generates Figures 2–6 for the manuscript. By default, figure files are written to a local `figures/` folder. |

## Output files and their role

| File | Contents | Use in the analysis |
|---|---|---|
| `outputs/disruptor_rule_flags_by_variant.csv` | Row-level rule flags for each colour-specific garment variant, including R1–R8 core disruptor indicators, R7b/R8b mismatch diagnostics, aggregate removable/retained/overall flags, garment metadata, and selected surface-reference information. | Provides the most complete reproducibility layer. Readers can trace which variants were flagged by each rule and recompute all aggregate shares from the row-level output. |
| `outputs/disruptor_rule_summary.csv` | Rule-level summary statistics for each rule and setting, including total rows, flagged counts, non-flagged counts, and shares. | Supports the manuscript percentages for individual rules and aggregate indicators, including the default, conservative, and expanded settings. |
| `outputs/disruptor_aggregate_summary.csv` | Subset of the summary table containing aggregate indicators such as `any_removable_disruptor`, `any_retained_barrier`, and `any_disruptor_overall`. | Supports the high-level results reported in Figure 2 and Section 3.1, including overall disruptor prevalence and removable versus retained barrier shares. |
| `outputs/disruptor_match_evidence.csv` | Evidence-level records for rule matches, including row ID, rule, setting, matched field, matched text, and garment category information. | Allows users to inspect the text or component evidence behind rule assignments. |
| `outputs/disruptor_trigger_diagnostics.csv` | Aggregated trigger counts by rule, setting, and matched term. | Provides the full tables behind top-trigger rankings shown in the results and figure panels, rather than only the top terms displayed in the manuscript. |
| `outputs/disruptor_category_diagnostics.csv` | Aggregated evidence counts by rule, setting, parent category, and detail category. | Supports category-level inspection of where rule evidence is concentrated and complements the category-level results shown in Figure 6. |
| `outputs/disruptor_regex_inventory.csv` | Regex-pattern inventory by pattern group, including include/exclude type, number of patterns, readable pattern labels, and raw regex strings. | Provides an audit trail for the executable rule definitions and supports reproducibility of the rule-boundary settings described in the manuscript. |
| `outputs/hardware_material_disclosure_summary.csv` | Summary of whether variants with R1–R3 hardware cues include material-specified hardware information, reported at garment-variant and evidence-match levels for each setting. | Supports the result that most hardware indicators are material-ambiguous in retailer data. |
| `outputs/disruptor_summary_readable.txt` | Human-readable processing summary, including processed row count, hardware material-disclosure diagnostics, brand counts, parent-category counts, and rule/aggregate shares. | Provides a quick audit summary for users who want to check the main numerical outputs without opening multiple CSV files. The CSV files remain the authoritative machine-readable outputs. |

## How to rerun the workflow

Install the required Python packages:

```bash
pip install -r requirements.txt
```

Place the input file in the working directory:

```text
6_JSONL_component_normalized.jsonl
```

Run the rule-evaluation script:

```bash
python scripts/01_evaluate_disruptor_rules.py
```

This creates or updates the `outputs/` folder and writes the derived CSV and TXT files listed above.

To regenerate the manuscript figures from the output tables:

```bash
python scripts/02_generate_figures.py
```

The figure-generation script expects the renamed output files listed in this README. By default, it writes figure files to a local `figures/` folder.

## Rule settings

The scripts implement three rule-boundary settings:

- **Conservative**: narrowest rule boundaries, capturing only the clearest cases.
- **Default**: main analytical specification used for the primary manuscript results.
- **Expanded**: broader but still plausible rule boundaries used for sensitivity analysis.

The manuscript reports default-setting results unless otherwise stated and uses conservative and expanded settings as sensitivity checks.

## Indicator groups

The workflow distinguishes between removable disruptors, retained barriers, and material-mismatch diagnostics.

| Group | Rule IDs | Description |
|---|---|---|
| Removable disruptors | R1–R3 | Hard-hardware indicators, including metal-specified or metal-conventional hardware, plastic-specified hardware, and material-ambiguous hardware cues. |
| Retained barriers | R4–R8 | Fabric-based attached trims, decorative or non-textile attachments, surface print or coating barriers, lining/multilayer presence, and secondary component presence. |
| Material-mismatch diagnostics | R7b, R8b | Diagnostic indicators comparing the material composition of hidden or secondary components with the selected surface reference. These diagnostics are reported separately from the core retained-barrier aggregate. |

## Notes on interpretation

The outputs identify **observable disruptor indicators** from retailer web data. They should not be interpreted as physical teardown results or direct recycling-process outcomes.

In particular:

- R1–R3 are cue-based hardware indicators. They indicate hardware-related wording in product information, not verified hardware composition.
- R3 captures material-ambiguous hardware cues, such as generic zip or fastener wording where the hardware material is not disclosed.
- R4–R8 capture retained-barrier indicators that may remain in the garment and affect sorting, feedstock purity, or downstream recycling suitability.
- R7 and R8 capture the presence of lining/multilayer and secondary-component structures.
- R7b and R8b are diagnostic mismatch indicators and are reported separately from the core R7/R8 presence indicators.
- Match-evidence and diagnostic tables are intended for audit and reproducibility. They may include multiple evidence records per garment variant.
